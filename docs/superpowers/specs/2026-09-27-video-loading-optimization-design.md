# 作品集视频加载优化设计

## 目标

在保持较高清晰度和现有视觉体验的前提下，缩短作品视频从打开查看器到可播放的等待时间，降低首屏和作品列表的无效网络消耗。

## 当前问题

- `public/work` 中 6 支视频总量约 230MB，最大单支约 85MB。
- 两支 AIGC 视频从 GitHub Release 跨地址加载，首次播放会增加连接与跳转成本。
- 查看器虽然使用 `preload="metadata"`，但视频元素在弹窗打开时立即创建；包含多个媒体时会同时产生元数据请求。
- 当前没有针对慢速网络的明确加载反馈。

## 方案

### 1. 视频编码

- 将站内视频统一转码为适合网页播放的 H.264 MP4。
- 使用 `faststart` 把 MP4 索引移动到文件头，使浏览器无需等待完整下载即可开始播放。
- 采用平衡画质参数：保留原始画幅比例，最长边上限 1920px；高帧率素材限制为 30fps；音频使用 AAC 128kbps。
- 以视觉质量优先的恒定质量编码为主，并设置合理码率上限，避免高动态画面产生异常大的文件。
- 不覆盖用户的源素材；网站目录中的发布副本替换为压缩版本。

### 2. 加载策略

- 视频默认只显示封面，不在查看器打开时请求视频文件。
- 用户点击播放按钮后才创建真正的视频元素并加载资源。
- 同一项目有多个视频时，每支视频独立按需加载，避免一次性并发下载。
- 播放器保留原生控制、内联播放与封面图；加载时提供低干扰的状态反馈，加载失败时提供重试入口。

### 3. 资源路径

- 将目前从 GitHub Release 引用的两支 AIGC 视频改为站点同源路径，避免跨域跳转和额外握手。
- 所有资源路径继续通过现有 GitHub Pages 基础路径逻辑解析，兼容本地开发和线上子目录部署。

## 组件边界

- 新增一个小型按需视频组件，负责封面、播放触发、加载状态、错误与重试。
- `MediaViewer` 只负责弹层、媒体列表和关闭行为，不承担视频请求状态。
- 视频清单继续由 `workCategories.js` 管理，不改变项目数据结构。

## 性能与体验约束

- 打开作品查看器时不得下载完整视频。
- 封面应立即可见，点击后才发起视频请求。
- 压缩后所有站内视频总量目标减少至少 35%，最大单支保持在 GitHub 100MiB 硬限制以内。
- 桌面端视觉布局、作品标题、封面和现有动效保持不变。
- 尊重浏览器原生播放策略，不强制自动播放或静音。

## 验证

- 对每支输出视频检查可解码、时长、尺寸、帧率、音轨与 `faststart`。
- 抽查开头、中段和结尾画面，确认无明显块状、色带、黑帧或音画不同步。
- 验证本地生产构建、代码检查和现有项目校验脚本。
- 在浏览器中确认打开弹层时仅加载封面，点击播放后才加载视频，并检查失败重试。

## 不在本次范围

- 不改变项目卡片设计、弹层布局或视频内容。
- 不引入第三方视频托管或付费 CDN。
- 不制作多清晰度自适应流媒体（HLS/DASH）。
