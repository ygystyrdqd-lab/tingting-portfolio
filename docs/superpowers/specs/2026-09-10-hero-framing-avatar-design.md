# 首屏双手取景框人物设计

## 目标

将个人介绍首屏现有橙色人物替换为用户提供的红裙人物图，并利用人物双手构成的取景动作设计一个专属的香槟金交互特效。效果需要醒目但克制，延续网站现有暗红、黑色与香槟金视觉系统，不增加明显的性能负担。

## 交互与动效

### 核心时刻：取景框激活

- 在人物双手之间叠加一枚细线香槟金矩形取景框，带四个短角标和克制的中心准星。
- 默认状态保持低透明度，避免静止时抢夺人物与标题的视觉层级。
- 鼠标进入人物区域时，取景框从中心向四周展开，持续约 550–700ms，使用自然减速曲线，不使用弹跳。
- 展开后，一道窄而柔和的扫描光由左向右通过一次；扫描结束后不持续循环。
- 手指附近用两个局部高光节点回应激活状态，只改变亮度和轻微尺度，不做高频闪烁。

### 指针反馈与空间层次

- 延用现有 `HeroAvatar` 指针追踪逻辑，通过 CSS 自定义属性传递归一化位移。
- 人物、取景框、背景装饰使用不同但很小的位移幅度，形成轻微景深视差。
- 人物移动幅度最小，取景框略大，背景方向相反；所有变化只使用 `transform` 与 `opacity`。
- 鼠标离开后各层平滑复位，取景框回到低亮静态状态。

## 组件边界

- `HeroAvatar` 继续负责图片加载、指针坐标与离开复位。
- 新增独立的取景框装饰节点，仅用于展示，不参与文档语义，并设置 `aria-hidden="true"` 与 `pointer-events: none`。
- 不引入 GSAP、Canvas、WebGL 或新依赖；使用现有 React 状态、CSS 变量、伪元素与关键帧完成。
- 图片加载失败时继续显示现有 `LT` 备用内容，特效装饰不得遮挡备用状态。

## 性能与无障碍

- 动态属性限制为 `transform`、`opacity` 和小范围阴影；扫描光限制在人物区域内。
- 扫描动画只在进入时播放一次，避免常驻 GPU 动画。
- 在 `prefers-reduced-motion: reduce` 下取消展开、扫描和视差移动，保留清晰的静态取景框与局部高光。
- 装饰层不接管鼠标事件，不影响页面导航、滚动或文本选择。

## 验收标准

- 首屏显示新的红裙人物图，素材清晰且比例正确。
- 桌面端人物双手、头部和主要服装完整，无右侧硬裁切。
- 取景框视觉上位于双手之间，并与手势形成明确关系。
- 悬停时能看到一次完整的展开与扫描反馈，移动指针时视差细腻、无抖动。
- 标题仍可清晰阅读，取景框不盖住正文或导航。
- 开启减少动态效果后页面仍完整可用。
- `npm run build`、项目校验脚本以及针对首屏的桌面端浏览器预览通过。
