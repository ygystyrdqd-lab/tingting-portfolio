# 首屏人物与标题二次优化设计

## 目标

解决 PC 端人物右侧裁剪问题，并进一步收紧 PC 端两行主标题。移动端保留人物大特写裁剪，同时将 `HI, I'M` 明确下移到首屏高度的 `50%`。

## 人物调整

- PC 与应用内网页视口（宽度大于 `620px`）的人物图片高度从 `170%` 调整为 `145%`，缩小约 `15%`，以展示更多右手和透明外套下摆。
- 人物图片继续顶部对齐；人物容器宽高和定位保持不变。
- 在宽度大于 `620px` 时启用右侧安全锚定，覆盖普通 PC 浏览器以及应用侧栏压缩后的网页视口：图片加载完成以及窗口或人物容器尺寸变化时，检测人物图片的实际右边缘。
- 若图片右边缘超过视口右侧 `32px` 安全线，只向左补偿实际超出的像素；未超出时补偿值为 `0px`。
- 安全补偿通过独立 CSS 变量叠加在现有水平居中和鼠标视差变量上，不额外改变图片缩放或人物容器位置。
- 宽度不超过 `620px` 的真正手机端不启用安全补偿，继续使用当前图片位置与裁剪方式；`621px` 以上的平板或应用内窄视口仍启用保护。

## 标题调整

- 常规 PC：`HI, I'M` 使用 `top: 38%`；`TINGTING.` 使用 `bottom: 25%`。
- 高度不超过 `760px` 的 PC：`HI, I'M` 使用 `top: 39%`；`TINGTING.` 使用 `bottom: 23%`。
- 平板保持当前 `top: 29%` 与 `bottom: 23%`。
- 手机：`HI, I'M` 使用 `top: 50%`；`TINGTING.` 保持 `bottom: 27%`。

## 范围

- 修改 `src/App.css` 的最终 Hero 构图规则与 `src/App.jsx` 中的 `HeroAvatar` 布局测量逻辑。
- 在 `HeroAvatar` 内增加仅负责计算 PC 右侧安全补偿的布局副作用，并在卸载时移除尺寸监听。
- 除已确认的 PC 图片高度 `145%` 外，不改变人物容器位置、标题字号、颜色、层级或字距。
- 不修改 GSAP Opening、鼠标视差、首屏内容或响应式断点。

## 验收标准

- PC 端人物右侧主体、更多右手和透明外套下摆可见，人物仍保持明显的大特写比例。
- PC 窗口尺寸变化后仍保持至少 `32px` 的右侧安全距离。
- PC 两行标题间距比当前版本进一步缩短。
- 手机端 `HI, I'M` 的顶部位置为首屏高度 `50%`。
- 手机端人物裁剪保持现状。
- 项目构建成功且无新增代码检查错误。
